## 检查必须区分的证据

| 证据 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 文件解码成功 | 流可以被解码 | 最后一个字是否读完整 |
| 所有源采样保留 | 装配没有删掉源样本 | 原始生成本身是否吞音 |
| ASR 与文案一致 | 识别器能够恢复文本 | 音节、词尾与连读是否自然 |
| 末尾有静音 | 文件末尾安静 | 静音前的字是否完整 |
| 很短的低电平窗口 | 局部幅值低 | 一定处于词间停顿 |
| 跳转后播放 0.8 秒 | 该时刻可加载并短暂播放 | 连续播放时不反复 seek 或掉音 |

检查全片、所有语言，分别记录自动结果、待听辨项与真实的人类复核。不能把工具无法听声音写成已经耳听通过。作者明确确认同一个版本，可以作为真实复核依据保存，不需要再次询问；已知硬性技术失败仍须修复。

## 共享流程的修正

1. 全局检查是预览、交付、打包和上传的前置条件，项目内检查是补充。
2. “角色”“predict”加入共享易错词；即使两个 ASR 都识别正确，仍显示听辨提示。
3. `final-review` 记录作者或实际人类操作者对最终音轨的复核，绑定视频、额外音轨、spec、字幕及人声源哈希。
4. 修改任一输入或使用旧检查版本时，`gate` 拒绝继续；真实复核不能覆盖技术不通过项。
5. 按影片意图设置可验证 spec，包括静止图片记忆题、反思停顿、单声道旁白等，不能把计划内静止画面误判为掉帧，也不能将意外缺陷声明为计划内容来放行。
